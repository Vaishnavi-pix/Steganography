TECHNICAL ARCHITECTURE

Encoding & Decoding Workflow

Two clear views of how a message is hidden in natural text and recovered from it.

01 / ENCODE

Hide a message in cover text

1

Convert the message

The secret message is converted into hexadecimal character codes. Each hex digit can then be represented by a preposition.

Message: "Hi"
Hex: 48 69
2

Map digits to prepositions

Each hexadecimal digit maps to one preposition from a password-derived ordering. The prepositions are assembled in sequence as the hidden payload.

Example digits: 4, 8, 6, 9
Mapped: in, at, on, by Illustrative mapping; the password determines the actual order.
3

Generate natural cover text

A language model writes a coherent passage around the required prepositions, concealing them in ordinary-looking text.

“Review the report in the folder at your convenience.”
SECRET MESSAGE HEX DIGITS PREPOSITIONS NATURAL COVER TEXT
02 / DECODE

Recover the hidden message

Decoding reverses the encoding steps. Provide the generated carrier text and the same password used to encode it; the decoder extracts the prepositions, maps them back to hexadecimal, and reconstructs the original message.

1

Find the signal

The decoder scans the carrier text and keeps supported prepositions in the order they appear, ignoring the surrounding cover words.

“...specifications in the attachment at your...”
Extracted: in, at, ...
2

Reverse the mapping

The password recreates the preposition mapping used during encoding. Each extracted preposition becomes its hexadecimal digit; every two digits form one character code.

in, at, ...
Password map: hex digit pairs
3

Restore the message

The hexadecimal character codes are converted back into text and returned as the decoded payload.

Hex pairs

Original secret message
CARRIER TEXT PREPOSITIONS HEX PAIRS ORIGINAL MESSAGE

Use the same password for both directions. If no password was set, decode with the default key.

STATISTICS

By The Numbers

STAT // 01

39.7% RECOVERY RATE

Out of all the test runs across different message lengths, the decoder extracted the original secret message with 100% perfection nearly 40% of the time (with shorter messages performing as high as 63.3%)

STAT // 02

114.5x CHARACTER EXPANSION RATIO

For every single character in your secret message (e.g., the letter "A"), the LLM generates roughly 114.5 characters of cover text to blend the preposition-encoded payload naturally into readable prose.

STAT // 03

30.5s MEAN LATENCY

On average, it takes about 30.5 seconds from the moment a trial is initiated for the model to craft and output the full encoded cover text.

COMMON QUESTIONS

Frequently Asked Questions

Traditional steganography alters noise bits in images or audio files (LSB modification). Linguistic steganography encodes payloads directly into plain text syntax, making it ideal for channels where only plain text is transmitted (e.g. emails, forum comments, chat messaging).
Information-hiding techniques can serve privacy-preserving applications as well as potential covert misuse. By sharing our source code and empirical evaluation data, we aim to encourage open research, reproducibility, and further study into steganographic detectability and safeguards.
